# 01 接入联系弹窗与推荐卡

> 适用对象：deck（dsh-mattpocock-skills-deck）/ palette（dsh-opencode-palette）/ im-companion / prompt（dsh-prompt）/ ilife（含六个 skill 包共用的总管面板）。
> 本文由 base 仓（dsh-featherhunter-plugin-base）维护；**执行者是各仓仓主**。base 仓不含五仓代码改动，本仓对五仓是零改动的。

## 0. 接入后得到什么

- 设置面板多一个入口（按钮或行）→ 点开 `<dialog>` 联系弹窗：
  - 群卡网格（飞书 / QQ / 微信群码），4 列上限，窄屏自动降列（4 → 2 → 1）；
  - Esc 关闭、点遮罩关闭、关闭后焦点回到触发元素；
  - 群码过期时**不展示过期图**，降级为「点击下方链接获取最新群码」的兜底链接；
  - 断网或清单拉取失败时，仍显示内置的飞书 + QQ 两码（内置基线），不白屏、不报错。
- 「作者的其他插件」推荐卡：5 条数据里排除自己剩 4 行，顺序按清单 `order`，整行可点、新窗口打开（`rel="noopener noreferrer"`）。
- **换码不发版**：维护者改 base 仓 `contact/` 并发 patch 后，客户端从 CDN（unpkg → npmmirror → jsDelivr）拉 `@latest` 清单，30 分钟缓存周期内自动换成新图与新有效期文案。五仓依赖版本不用动。

## 1. 前置条件

- React 18 或 19（peerDependencies: `^18 || ^19`）。宿主已有 React，base 的 client 产物**零 import、不含 React**。
- 构建环境 Node 20+（纯 ESM 包）。
- 宿主能拿到 React 对象（五仓都是宿主注入，如 `ctx.getReact()` 或各仓现有的 getReact()）。

## 2. 安装（钉精确版本）

```sh
npm install --save-exact dsh-featherhunter-plugin-base@0.0.1
# pnpm add -E dsh-featherhunter-plugin-base@0.0.1
```

- **钉精确版本**：组件/渲染器代码随包版本走；数据（清单 + 图片）走 CDN `@latest`，换码不需要升级依赖。
- 升级 base 是独立动作：改这一行 → 重新构建 → 按《03-CI与发布.md》的升级流程走。
- 发布物只含 `dist/ data/ README.md LICENSE`；三入口 `./core` `./client` `./node`（另有 `./package.json`）。

## 3. 三行接入

```ts
import { createBaseUI } from "dsh-featherhunter-plugin-base/client";

const base = createBaseUI(React, { lang: "zh", selfId: "deck" });
```

然后按仓内现有渲染方式放组件：

- 按钮：`<base.ContactButton />`（16px 线框二维码图标，纯图标无文字；`aria-label` / `title` 默认「联系我们」）
- 行式入口：`<base.ContactRow label="联系我们" hint="扫码进群反馈" />`
- 推荐卡：`<base.AuthorPlugins />`
- 命令式：`const close = base.openContactModal({ trigger })` → 返回关闭函数；`base.closeContactModal()`；`await base.preloadContent()`（提前预热清单和图片，不阻塞首屏，失败不 reject）。

### 3.1 createBaseUI 选项

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `lang` | `"zh" \| "en"` | 自动探测 | 不传时依次看 `document.documentElement.lang` → `navigator.languages` → `zh` |
| `selfId` | `string` | 无 | 本仓在清单 `plugins[].id` 里的 id（deck / prompt / palette / im / ilife），推荐卡据此排除自己 |
| `columns` | `1..4` | 4 | 宽屏列数；硬上限 4，窄屏仍会自动降列 |
| `fallbackUrl` | `string` | 无 | 群码过期时的兜底链接；不传则用清单里的 `fallbackUrl` |
| `texts` | `TextOverrides` | 无 | 覆盖文案，key 见 `MESSAGES`（contact/contactHint/kicker/modalTitle/welcome/scanHint/mobileHint/close/copyHint/copied/expired/fallback/plugins，以及群卡渠道名 channelFeishu/channelQq/channelWechat） |
| `maxRows` | `number` | 5 | 推荐卡最多行数 |
| `showSelf` | `boolean` | false | 推荐卡是否显示自己 |
| `manifestUrl` | `string` | 无 | 指向自建 https 清单（必须是 https 且在白名单域名），测试/私有镜像用 |
| `fetchImpl` | `FetchLike` | 全局 fetch | 注入 fetch（测试/受限环境） |
| `contentLoader` | `ContentLoader` | 无 | 注入自定义加载器（测试用） |

### 3.2 组件 props

- `ContactButton`: `className?`, `title?`, `size?: 14 | 16 | 18`（纯图标按钮，不渲染文字）
- `ContactRow`: `className?`, `label?`, `hint?`
- `AuthorPlugins`: `className?`, `title?`, `lang?`, `selfId?`, `showSelf?`, `plugins?`, `maxRows?`

### 3.3 最小示例（JSX）

```tsx
import * as React from "react";
import { createBaseUI } from "dsh-featherhunter-plugin-base/client";

const base = createBaseUI(React, { lang: "zh", selfId: "deck" });

export function SettingsFooter() {
  return (
    <div className="settings-footer">
      <base.ContactRow hint="扫码进群反馈" />
      <base.AuthorPlugins />
    </div>
  );
}
```

### 3.4 最小示例（手写 createElement，deck / palette 这类无 JSX 的仓）

```ts
const h = React.createElement;
h("div", { className: "settings-footer" },
  h(base.ContactRow, { hint: "扫码进群反馈" }),
  h(base.AuthorPlugins, {}),
);
```

## 4. 逐仓落点

| 仓库 | 现有槽位 | 入口放哪 | 推荐卡 | client 产物托管方式 |
| --- | --- | --- | --- | --- |
| deck | `settings.plugins.tab` order 40 + `settings.section` order 18（MattSkills） | MattSkills 面板底部放 `ContactRow` | 替换现有「作者其他插件」四行卡为 `AuthorPlugins` | 内联拼接：把 `dist/client/index.js` 作为本地文件内联进产物 |
| palette | `settings.plugins.tab` order 30 + `settings.section` order 16 | 调色板 section 底部 | 替换现有四行卡 | `INLINE_PACKAGES` 逐文件登记（runtime/client.ts） |
| im-companion | 仅 `settings.section` order 22 | 面板内放 `ContactRow`；原自绘二维码弹窗改调 `base.openContactModal` | 现状无推荐卡；要加就用 `AuthorPlugins` | tsdown 依赖打包 |
| prompt | `settings.section` order 50 | 提示词模板 section 底部 | 替换 `src/client/settings-links.ts` 的 `MORE_PLUGINS` 四行卡 | tsdown 依赖打包 |
| ilife | 总管 `dsh-life-pack` `settings.section` order 21「爱生活」 | 总管卡入口（PANEL_LINKS 图标行 `iconOnly` 按钮，或 MORE_PLUGINS 加一行） | 总管卡内放 `AuthorPlugins` | `tsc -b` + `build:client`，作为 dsh-life-pack 的源文件/依赖打进 |

约定：**每个仓只加一处入口、最多一处推荐卡**；不要在两个槽位重复放同一个弹窗入口。

## 5. ilife 特例

- 设置面契约只允许一个 section（`{ id: "dsh-life-pack", order: 21 }`）：**不要给六个 skill 包各加 section/入口**，只动总管。
- 六个 skill 的 HTML 页面拒收 `<img>`：弹窗只在 React 设置面出现，不受该限制；不要把二维码塞进 HTML 页。
- ilife 构建链是 `tsc -b` + `build:client`：把 base client 单文件作为 dsh-life-pack 的一个源文件/依赖打进，确保全仓只有一份 React 实例。
- 定时刷新沿用 ilife 现有 `ci.yml` 加 schedule 的方案（不新增 workflow，见《03-CI与发布.md》）；做不到就退化为随发版更新，并在仓内 README 写明滞后。

## 8. 常见失败与回退

- **构建链吃不下单文件** → 改用内联方式（deck / palette 已有内联机制）；不要为此改 base 包。
- **多个 React 实例**（hooks 报错 / 渲染异常）→ 确认用的是宿主 React；client 产物不含 React，若仍出现，检查宿主是否把依赖里的 react 又打了一份。
- **弹窗样式缺失 / 错位** → 样式由 `ensureBaseStyles` 自动注入（`style#dsh-base-ui-style`）。宿主 CSP 禁止内联 style 时，构建期把导出的 `BASE_CSS` 写进宿主样式表，并保证只注入一次。
- **按钮点击无反应** → SSR 环境没有 `document`，`openContactModal` 会空操作；在客户端 effect / 挂载后调用。
- **清单拉不到** → 弹窗自动降级到内置基线，不需要报错弹窗；失败结果也缓存 30 分钟，等下一周期或刷新页面重试。
- **想临时换清单源** → `createBaseUI(React, { manifestUrl })`，必须 https 且在白名单域名（unpkg.com / registry.npmmirror.com / cdn.jsdelivr.net）。
- **回退** → 删掉新增的 import 与组件即可回到接入前，不影响宿主其他功能；旧实现若已删，用 git revert 该仓那一个提交。

## 9. 数据与文案的维护边界（给仓主）

- 群卡、推荐文案的唯一真源是 base 仓的 `contact/groups.json` 与 `contact/plugins.json`；**不要在各仓写死**。
- 改文案 / 加群：在 base 仓改数据 → `contact:update` → 版本 patch → `npm publish`（一条命令见《03-CI与发布.md》）→ 客户端 `@latest` 自动生效，五仓无需发版。
- 推荐文案里的数字必须带 `verifiedAt`；`doctor` 对超过 90 天未核对的条目提示「数字可能已过期」。
- README 侧的四块内容（联系卡 / 星标历史 / 致谢表 / 更多插件）由 `readme:sync` 统一改写，迁移步骤见《02-README四块迁移.md》。
