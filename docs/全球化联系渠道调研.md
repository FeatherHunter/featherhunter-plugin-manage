# 全球化联系渠道调研（FeatherHunter 插件矩阵）

> 调研对象：FeatherHunter（GitHub 名下 dsh-mattpocock-skills-deck、dsh-opencode-palette、dsh-prompt、dsh-im-companion、ilife），面向全球开发者。
> 现状：QQ 常驻群、微信限时群（7 天过期需周更）、飞书常驻群、GitHub Issues。维护者为中文个人开发者，要求维护成本低。
> 方法：只认一手来源（官方文档、源仓库、平台帮助页）。凡被 Cloudflare 拦截未能全文抓取的页面，仅引用其官方帮助中心入口，不转述二手结论，并在正文中注明。
> 日期：2026-10-23；调研人：调研子代理。

## 0. 结论先行（给维护者的一页决策）

1. **第 1 追加：GitHub Discussions（组织级，零成本，必做）。** 理由：与 Issues 同处 GitHub，用户零跳转、SEO 可索引、可转 Issues、可锁定/标答/举报/拉黑，全是现成官方能力；欧美开源用户默认先看仓库有没有 Discussions，没有就默认“只用 Issues 提问”，体验差。落地约 30 分钟。
2. **第 2 追加（二选一，推荐先不做、等 Discussions 跑顺再定）：Discord 只读公告 + 慢速问答频道，或 X（Twitter）只读公告账号。** 若非要现在加一个实时渠道，选 **Discord** 而不选 Telegram/Matrix/Reddit：欧美开发者实时社区基本盘在 Discord；Telegram 在欧美开源圈是补充而非主流；Matrix 用户少且需自建/选 homeserver；Reddit/Stack Overflow 不可运营、只能“被讨论”。
3. **不加：Matrix、Telegram 公开群、Reddit 子版块、Stack Overflow 官方标签、邮件列表、独立文档站重投入。** 不是它们不好，而是在“单人中文维护者”约束下 ROI 为负：要么没人来（Matrix/Reddit 新版块冷启动），要么来了守不住（Telegram 垃圾信息重、Reddit/SO 不可控、邮件是工单黑洞）。

## 2. 欧美场景：Discord vs GitHub Discussions 取舍

| 维度 | GitHub Discussions | Discord |
|---|---|---|
| 用户路径 | 到仓库即达，无需新注册。官方定位：“不需跟踪、不直接关联代码的开放式对话” ([About discussions](https://docs.github.com/en/discussions/collaborating-with-your-community-using-discussions/about-discussions)) | 需注册 Discord + 加服务器 + 找频道；三跳流失。定位是社区服务器实时聊天 ([Discord Communities](https://discord.com/community)) |
| 内容沉淀/SEO | 可索引、可标答、可置顶、可转 Issues；是项目的知识库 | 聊天流，沉淀差；好答案 3 天后找不到（这是实时聊天的结构性缺陷，不是配置问题） |
| 版主成本 | 官方自带：标答/锁定/关闭/转 Issues/删改/分类 ([Moderating discussions](https://docs.github.com/en/discussions/managing-discussions-for-your-community/moderating-discussions))；加锁定会话 ([Locking conversations](https://docs.github.com/en/communities/moderating-comments-and-conversations/locking-conversations))、举报 ([Reporting abuse or spam](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam))、组织级拉黑 ([Blocking a user from your organization](https://docs.github.com/en/communities/maintaining-your-safety-on-github/blocking-a-user-from-your-organization)) | 需自建规则：验证等级、AutoMod、慢速模式、频道权限、机器人值守；官方安全能力在 [Safety Center](https://discord.com/safety)，但全要手动配。单人维护者≈ 7×24 值班 |
| 反垃圾 | GitHub 账号门槛 + 举报 + 锁定 + 拉黑，链路闭环（上列 4 篇即证据） | 开放邀请链接=机器人必到；AutoMod 能挡一部分，挡不住“真人广告+深夜刷屏”；需人工复核 |
| 时差 | 异步，无时差压力；可写 SLA“48h 内回” | 同步，欧美白天=北京时间深夜；不回显得死群，回了熬死人 |
| 适用题型 | 怎么用、是不是 bug、路线投票、公告 | 闲聊、结对、发版蹲守、活动 |
| 取舍结论 | **默认选项，先开它**：覆盖 80% 需求，成本 20% | **增强选项，后开它**：只在 Discussions 日活稳定、有志愿者版主之后再开；一开就必须配规则（见 §4） |

一句话：**Discussions 是“省电的同步”，Discord 是“费电的同步”。单人维护先省电。**

## 3. 排序推荐（最少追加 1–2 个）

- **P0（本周做）：组织级 GitHub Discussions + 联系矩阵页。**
  - 在组织（FeatherHunter 名下选一个主仓库，如 dsh-mattpocock-skills-deck）按 [Quickstart](https://docs.github.com/en/discussions/quickstart) 开启组织 Discussions：Settings → Features → Set up discussions → 写欢迎帖。
  - 分类建议 4 个：Announcements（仅维护者）、Q&A（标答）、Ideas（投票）、Show & tell（用户作品）。依据：[About discussions](https://docs.github.com/en/discussions/collaborating-with-your-community-using-discussions/about-discussions) 明确支持公告/问答/投票/分享四类用法。
  - 每个仓库 README + GitHub Pages（如有，按 [About GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages) 托管）放同一“联系矩阵”：Issues=报 bug/提需求｜Discussions=问怎么用/聊想法｜QQ/飞书=中文闲聊｜微信群=限时（注明过期机制）｜邮箱=商务/安全。
  - Issues 加模板分流：bug 表单/需求表单 + 第一行“提问请去 Discussions”。能力依据：[Issue forms 语法](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms)。
- **P1（下月视精力二选一）：Discord 服务器（需配 AutoMod+慢速+只读公告）或 X 公告账号。**
  - Discord 最小可用形态：#announcements（只读）、#faq-please-read（只读）、#help（慢速 1h）、#showcase；开社区服务器按 [Discord Communities](https://discord.com/community) 指引，安全按 [Safety Center](https://discord.com/safety)。
  - X 最小可用形态：只发 release/公告，不回私信；Bio 写“Support → GitHub Discussions 链接”。
  - 二者都不做客服，客服只收敛到 Discussions。二选一只因维护者只有一人。
- **明确不做**：Matrix 新房间、Telegram 英文公开群、Reddit 自建子版块、SO 官方运营、邮件支持。原因见 §1 表格；每一条都对应“要么没人、要么守不住”。

## 4. 零成本落地步骤（复制即用清单）

### 4.1 GitHub Discussions（约 30 分钟，零费用）

1. 选主仓库 → Settings → Features → Set up discussions（组织讨论选该仓库为 source repo）。来源：[Quickstart](https://docs.github.com/en/discussions/quickstart)。
2. 建 4 分类 + 欢迎帖（置顶《去哪提问》+ 联系矩阵 + 中英文双语，英文在前）。
3. 每个插件仓库 README 顶部加同一段 Contact（英文在前，中文在后），链接到组织 Discussions + Issues 模板。
4. Issues 加两套 issue forms（Bug / Feature）+ config.yml 关空白 Issues。来源：[Issue forms 语法](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms)。
5. 加 CODE_OF_CONDUCT.md（用 GitHub 模板一键生成）。来源：[Adding a code of conduct](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/adding-a-code-of-conduct-to-your-project)。
6. 写版主 SLA：Q&A 48h 内回（先标答后完善）、Ideas 每月汇总一次、Announcements 只发 release。
7. 第一周把微信群/QQ 群里的高频问题亲手搬 5–10 条到 Q&A 并标答（冷启动种子）。

### 4.2 若开 Discord（约 2 小时，零费用，不含后续值班）

1. 按 [Discord Communities](https://discord.com/community) 建社区服务器；先开 4 频道（见 §3）。
2. 按 [Safety Center](https://discord.com/safety) 开：最高验证等级 + AutoMod 关键词（spam/scam/广告）+ 全员慢速 + 新人 10 分钟禁言。
3. #faq-please-read 置顶：“提问先看 Discussions Q&A，本群只做闲聊；深夜（北京时间）无人值班”。
4. 邀请链接用“永不过期但可撤销 + 会员审核”，被轰炸时一键暂停邀请。
5. 找 1–2 个英文志愿者版主后再放量宣传，否则保持“小而只读”。

### 4.3 联系矩阵页（约 1 小时）

- 用 GitHub Pages 托管一页 `contact.md`（能力见 [About GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)），或直接写在组织 profile README；内容= §3 的矩阵 + 各群二维码/链接有效期说明（微信 7 天过期如实写，老外看得懂）。

## 5. 反垃圾与维护注意事项

1. **分流即防洪**：Issues 只收可复现 bug/明确需求，其余一律转 Discussions（官方支持 issue↔discussion 互转，见 [Moderating discussions](https://docs.github.com/en/discussions/managing-discussions-for-your-community/moderating-discussions)）。模板里写死，不留“我该发哪”的犹豫。
2. **锁定 > 争吵**： heated 讨论直接锁（可注原因、仅协作者可评），来源：[Locking conversations](https://docs.github.com/en/communities/moderating-comments-and-conversations/locking-conversations)。锁帖不丢人，熬夜吵架才丢人。
3. **举报链路**：discussion/comment/issue 均可 Report content 到仓库管理员或 GitHub Support（来源：[Reporting abuse or spam](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)）；组织级对 spam 账号 Block + 关闭其全部 issues/PRs/discussions（来源：[Blocking a user](https://docs.github.com/en/communities/maintaining-your-safety-on-github/blocking-a-user-from-your-organization)）。
4. **行为准则前置**：CODE_OF_CONDUCT 就位后再放量宣传，否则封人无据。来源：[Adding a code of conduct](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/adding-a-code-of-conduct-to-your-project)。
5. **微信群过期机制保留但要翻译**：英文页如实写“WeChat group QR expires in 7 days; re-issued weekly”，并给 Discussions 作为永不过期入口——把“中国特色”变成“双轨制”而不是“障碍”。
6. **语言策略**：Discussions/Issues 默认英文（标题英文），可用中文正文+机翻；QQ/微信/飞书默认中文。README 双语但英文在前——这是给欧美开发者的第一印象分。
7. **SLA 与熔断**：公开写“个人维护，48h 回复；北京时间深夜无值班”；连续被 spam 轰炸时先锁全场再处理，不要在线对线。
8. **数据主权**：知识沉淀只认 Discussions（可索引、可标答），Discord/微信群的好答案每周搬一条回 Q&A。否则同样的题每月答三遍。
