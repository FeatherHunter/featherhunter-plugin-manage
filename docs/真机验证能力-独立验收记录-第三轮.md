## 3. 剩余卡点与最小修法

### 3.1 【必修】D5：全局参数错误 + `--json` 不输出 JSON
- 现状：`dsh-verify --bogus --json` → exit 2，stdout 0 字节；AGENTS-USAGE.md:50 承诺输出 `stage:"usage"` 的失败 JSON。
- 最小修法（二选一）：
  1. **改实现**（推荐）：在顶层解析错误分支里，若 argv 中出现 `--json`，向 stdout 打一行与命令级同形的 JSON（`command` 省略或置 `null`），例如 `{"schemaVersion":1,"ok":false,"error":{"code":"invalid-input","message":"unknown option(s): --bogus","hint":"...","stage":"usage"}}`；stderr 保持现状。约 3–5 行。
  2. **改文档**：把 AGENTS-USAGE.md:50 的"`--json` 时 stdout 仍是那一段失败 JSON"限定为"有命令时"，并明说无命令时只打 stderr。
- 风险：现状会让脚本在"全局旗标打错"时拿到空 stdout 却 exit 2，JSON 消费方会解析失败。

### 3.2 【建议】任务 A 的三处"要推断一下"
- README.md:132–138 的校验片段默认 cwd 就是 run 目录（用 `.`）。建议在片段前加一行 `cd <work-root>\runs\<runId>`（或在正文写"在报告所在目录执行"）。1 行。
- README.md:72 对 `clientEntry` 只说"包内客户端入口的相对路径"。建议补一句"从本包 `package.json` 的 `exports` 里找（例如 `"./client": "./lib/client.js"`）"。1 句。
- README.md:71 的选择判据只到"挑你想留下证据的那个"。建议补一句"多个都满足时，选你日常启动 DSH 用的那个（桌面端通常是 `desktop`，Web 端通常是 `web`）"。1 句。

### 3.3 【可选】短命令写法冗余
- README.md:42/85 用 POSIX 形式 `node_modules/.bin/dsh-verify`，README.md:49 又补 PowerShell 形式。实测 pwsh 7.6.9 两种都能跑，不是缺陷；若想更省心，可在 :42 后直接加括号注"PowerShell 亦可写 `.\node_modules\.bin\dsh-verify.cmd`"。
