# 五仓设置面板现状盘点

> 口径：只读盘点（未改任何仓内文件、未跑构建）。五仓 = 4 个单仓插件 + ilife（1 个总管 dsh-life-pack + 6 个单品插件）。
> 目的：为"设置面板里加一行 → 点开显示群二维码"这一新入口选落点。日期 2026-10-24。

## 速览

## 统一化难度评估

### 已经同形的部分（可直接复用）

1. **注册形一致**：五仓都是 `slots.register({name:'settings.section', id, order, label: ()=> <字符串>}, 组件)`；其中三仓（mattdeck／palette／dsh-prompt）**同时**注册 `settings.plugins.tab` 与 `settings.section` 两个入口，im-companion 与 ilife 只注册 `settings.section`。
2. **"入口区"布局一致**：页头右上角 🌟（仓库）＋💬（issue）两枚图标 ＋ 页尾"作者其他插件"四行卡——mattdeck（`SettingsPage.ts:31-36`＋`:91-103`）、palette（`runtime/client.ts:1704-1765`）、dsh-prompt（`settings-links.ts:25-30`＋`:205`）、ilife（`nav.ts:114-117`＋`:147-168`、`client.ts:1114-1138`）**四处逐字同形**：行＝包名＋一句说明＋外链图标，数据表与组件分离。
3. **React.createElement 手写、无 JSX**：mattdeck／palette／dsh-prompt／ilife 四仓同选型（只有 im-companion 的实页是命令式 DOM）。`h(...)` 的调用形状因此是相通的。
4. **弹层要跳出滚动容器**：palette 的复盘（`interaction-surface-141.md:87`）与 ilife 的 `<dialog>.showModal()`（`client.ts:1207`）、dsh-prompt 的 `TopPortal`＋`MODAL_Z`（`settings-links.ts:5-11`）说的是同一件事——设置页可滚、有层叠上下文，`position:absolute` 会被裁。

### 三个 outlier

- **im-companion**：唯一"React 外壳＋命令式 DOM"的仓；入口 label 硬编码中文（`index.ts:149`）；但它**是唯一已经实现过二维码弹窗的仓**（`connect-flow.ts` 全套：`data:` URL 白名单、倒计时、换码、轮询）。新入口若另写一套，会与它并存两套二维码 UI。
- **ilife**：唯一的"两层导航"（section → children 页签）与"六家共用一个面板实现"；行表是硬编码中文的数据（不是 UI 代码）；i18n 只有门禁没有词条。加"仓级"入口只能进总管卡（`PANEL_LINKS`／`MORE_PLUGINS`），加"每家都有"的入口才走 `extra` 钩子。另有一条硬约束：`dsh-client-contract.md:148-153` 规定"单品不得再注册独立 section"。
- **palette**：i18n 内联在 120 KB 单文件里，加一行文案要动同一个文件；没有 `files` 白名单（全发）。

### 一套共用方案必须容纳的事

| # | 约束 | 影响 |
|---|---|---|
| 1 | **五套 i18n，无一共用**：YAML→生成器（mattdeck）／内联表（palette）／单表 `STR`（dsh-prompt）／按目录 YAML→虚拟模块（im-companion）／只有门禁没有表（ilife） | 共用组件不能自带文案表，必须**接收文案 prop**（或宿主注入的 `tr`） |
| 2 | **QR 图片没有现成"随包发布"通道**：五仓 `files` 全都不含 `assets`（palette 无白名单但客户端也不引图）；组件内被验证过的图片通道只有两种：`data:` URL 由 RPC/宿主给（im-companion 的二维码与头像）与**源码内 base64 内联**（palette 字体产物 `font-face.ts`、ilife 手册里的 6 张 JPEG） | 要么把二维码 base64 内联进产物，要么走 RPC 取 `data:image/...;base64,`（复用 im-companion 的 `safeQrSrc` 白名单），要么新增 host 静态路由（五仓皆无先例） |
| 3 | **弹层三种切断法**：body portal＋z-index（dsh-prompt）／原生 `<dialog>.showModal()` top layer（ilife）／自绘 modal（im-companion） | 共用弹层建议直接用 `<dialog>.showModal()`：唯一不依赖 z-index、且 ilife 已在真机验证过 |
| 4 | **行必须可点击而非外链**：四处"作者其他插件"的行都是 `<a href target=_blank>` | 二维码行是 `<button>`，共用组件要把"外链行"与"动作行"抽象成同一列表的两种 type |
| 5 | **入口 label 的 i18n 程度不一**：ilife 硬编码中文（"爱生活"，且六家行表 title/hint 全中文）；im-companion 入口 label 已 i18n，但其二维码流程文案硬编码在 connect-flow.ts | 新入口统一 label 来源时只差 ilife 这一处（改一个硬编码字面）；顺手别混进别的改动 |
| 6 | **设置面契约**：ilife 只许一个 section；mattdeck／palette／dsh-prompt 一个页面注册两个槽 | 共用入口最好做成"一个小组件＋一行数据"，由各仓自己决定挂哪一组 |
| 7 | **禁 DOM／禁 node 的纪律**：ilife 客户端 `禁 node、禁 DOM 直写`（`plugin-calorie/src/client.ts:4`），取数只经 RPC | 若入口要"取群码"，只能经 host 通道；不能 `fetch` 静态文件 |
| 8 | **验收墙**：ilife 的技能 HTML 页拒收 `<img>`＋惰性加载（`skill-chef/src/view/pageSection.ts:8`） | 若二维码只在设置面板（React 面）出现，不受此限；一旦进 HTML 页就得内联 data URI |
