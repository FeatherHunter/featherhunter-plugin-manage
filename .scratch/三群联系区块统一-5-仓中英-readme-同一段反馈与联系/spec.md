## Problem Statement

读者在不同插件 README 尾部只看到单个飞书二维码，各仓标题与引导语各说各话（反馈与联系 / 加入我们 / 交流群），mattpocock 仓还挂着一个名叫话题群的旧二维码。用户希望把同一批三个交流群（QQ 常驻、微信限时、飞书常驻）一次性铺到全部插件 README，中英文一致，让读者无论从哪个仓进来看到的都是同一段联系方式。

## Solution

把五个目标仓的中英文 README 尾部联系区块统一为同一段反馈与联系区块：标题锁死，引导语沿用调色板仓那句欢迎语加一行分流说明，三图横排并列（QQ 常驻、微信限时、飞书常驻），微信注明 7 天有效、过期走 QQ 或飞书。源头图片只留当前管理仓，配一个同步脚本，一次换图一次脚本即可全量覆盖全部目标仓，作者后续在当前工作区一句话即可触发同步。

## User Stories

1. As a 插件读者， I want a 在任何一个插件 README 尾部看到同样的反馈与联系区块， so that 不用猜哪个群才是官方群。
2. As a QQ 用户， I want a 扫到常驻 QQ 群并看到群号， so that 加群失败时还能手动搜群号加入。
3. As a 微信用户， I want a 看到当前有效的微信群二维码并知道它是限时的， so that 过期时不会反复加过期码，而是转用 QQ 或飞书群。
4. As a 飞书用户， I want a 扫到常驻飞书群， so that 一次加入长期有效。
5. As a 英文读者， I want a 在英文 README 看到与中文一致的 Feedback and Contact 区块， so that 不用切回中文版找群。
6. As a mattpocock 仓的老读者， I want a 不再被旧话题群文案误导， so that 直接加入与别仓同一个飞书群。
7. As a 作者， I want a 每周只换一次微信图并跑一次同步就全仓生效， so that 不用逐仓改十处文案和图片。
8. As a 作者， I want a 在当前管理仓一句话即可触发同步， so that 不用记脚本参数和目标清单。
9. As a 贡献者， I want a 在联系区块看到统一的 ISSUE 分流说明， so that Bug 走 ISSUE、闲聊走群，不混淆。
10. As a 移动端读者， I want a 三图宽度适中、横排可读， so that 手机上也能一次扫完。
11. As a 离线或代理环境读者， I want a 图片随包发布而不是引用外部链接， so that 无网络也能看到二维码。
12. As a 后续维护者， I want a 规范词只认反馈与联系， so that 不再出现加入我们、交流群、话题群等别名回潮。

## Implementation Decisions

- 术语锁死：中文标题只用反馈与联系，英文标题只用 Feedback and Contact，sub 只用 CONNECT；ilife 因整文件是 Markdown 风格，用二级标题对等落地，不强行改全文风格。别名加入我们、交流群、话题群一律废弃。
- 引导语锁死：中文第一行沿用调色板仓欢迎语，第二行写分流说明，第三行写三群属性，末行写微信过期提示；删掉图片每周由作者更新一句。英文含义对等，不逐字直译俚语。
- 三群定义锁死：QQ 群为常驻并明示群号，微信群为限时并注明 7 天有效与每周更新节奏，飞书群为常驻并在图内组织信息保持不变。
- 落点数量：中文 5 处全替换，英文 4 处（mattpocock、调色板、im-companion、prompt），其中 im-companion 英文版为新增块而非替换；ilife 无英文版不建。
- mattpocock 旧话题群块作废：确认与别仓为同一个飞书群，不再保留双块，一刀切替换为统一块。
- 统一管理方式：复制式统一，不用中央链接引用，不用子模块。源头图片只留管理仓并锁死三个文件名；各目标仓用同名复制加各自资源目录前缀；同步脚本放在管理仓，一次执行覆盖全部图片与全部 HTML 文案块。
- 图片规格：三图宽度统一为 260，alt 文案统一含群名与平台，边框样式沿各仓现有习惯保留差异之外的最小改动（例如 prompt 仓保留圆角边框类）。
- 微信周更流程：作者用新截图覆盖源头微信图后跑同步脚本即可；正文不写死具体到期日期，日期只活在图片水印里，避免每周改十处文案。
- 飞书限时预案：当前飞书为永久有效，本次不做额外分支；若未来飞书变为限时，复用与微信相同的周更链路，不另起机制。
- 测试缝选择：最高缝为 README 渲染后的联系区块（读者肉眼所见）。不新增代码缝；同步脚本自身是唯一的执行缝，调用一次即覆盖全部落点，缝数量保持为一。

## Testing Decisions

- 好测试只看外部行为：README 预览能看到统一标题、统一引导语、三图并列可扫，不测实现细节。
- 必测项：每处落点的标题词、引导语逐字一致（除资源前缀与 ilife 标题语法外）；三图文件存在且可渲染；QQ 群号可见；微信过期提示行存在；英文块含义与中文一致。
- 参照物：以调色板仓现有欢迎语为文案基准，以三张源头群图为图片基准，逐处对照。
- 同步脚本测试：换一张源头微信图后跑脚本，全部落点图片字节一致更新且文案块未被意外改动；重复跑脚本结果幂等。
- 不测项：二维码码值本身的解码目标、star 历史图、外链徽章均不在本次验收内。

## Out of Scope

- 不碰各仓功能代码、设置面板、技能逻辑，只动 README 联系区块与配套图片资源。
- 不建 ilife 英文版，不补各仓缺失的其他翻译。
- 不做定时任务或自动推送：微信更新仍由作者手动换图触发，不做无人值守的过期检测。
- 不引入中央图片服务或外部图床，不改各仓发布流程。

## Further Notes

- 词汇依据：管理仓根目录术语表已收录反馈与联系与三群定义，后续讨论以它为准。
- 触发口令约定：以后在管理仓说更新微信图并同步或同义词，即指覆盖源头微信图后跑同步脚本全量覆盖，不用再复述目标清单。
- 微信示例日期（如 10 月 30 日前有效）仅为图片水印现状，正文不锁定该日期，避免把临时日期写进规范。
