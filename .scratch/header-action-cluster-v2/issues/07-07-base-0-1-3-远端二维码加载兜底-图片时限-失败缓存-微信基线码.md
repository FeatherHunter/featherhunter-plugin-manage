# 07: base 0.1.3 远端二维码加载兜底（图片时限 / 失败缓存 / 微信基线码）+ 五仓换代重装

**What to build:** 修票 06 真机取证发现的二维码降级缺陷，发布 base 0.1.3 并五仓换代重装。**缺陷现象**：web profile 里首次打开「联系我们」弹窗时，微信群卡片没有二维码（只剩有效期文案 + 「点此获取最新群二维码」降级按钮），飞书/QQ 两卡正常。**三条根因**：(1) packages/base/src/client/content.ts:17 的 MANIFEST_TIMEOUT_MS=1500 被所有请求共用，13KB 的二维码 PNG 与 manifest 一样只有 1500ms；本机冷启动 cdn.jsdelivr.net TLS 实测 2010ms > 1500ms，图片请求被 abort，永远拿不到；(2) content.ts:299-308 + getCached 把「全通道失败」的 null 结果缓存 30 分钟，一次冷启动失败后半小时内每次打开弹窗都不重试（packages/base/src/client/index.ts:166-168 content 为 null 直接 return）；(3) packages/base/scripts/build-data.ts:31 的 BUNDLED_PLATFORMS 只有 feishu/qq，微信二维码只有远端来源（baseline.ts:85-88 kind=remote），远端一失败就没有任何码可显示——而 build-data.ts:32-33 的 QR_BASE64_BUDGET=80KB 注释写的是 three codes，预算本就按三个码预留。**修法**：(a) 图片请求用独立更长时限（新增 CONTENT_IMAGE_TIMEOUT_MS 默认 6000ms），manifest 保持 1.5s，补「慢图 2s 仍成功 / 超过 6s 才降级」测试；(b) 失败结果改短 TTL（60s）+ 成功仍 30 分钟，补「失败 60s 后重试、成功 30 分钟复用」测试；(c) 把 wechat 加入 BUNDLED_PLATFORMS 并 npm run build:data 重新生成 baseline.ts（发布清单仍保留 remote 以便远端刷新；基线码受 validUntil 过期逻辑约束，过期不展示），补「baseline 三组三码齐全」断言。随后 base 升 0.1.3、重走发布流程（GitHub Actions 手动 publish）、五仓依赖升 0.1.3 并重建内联产物（banner v0.1.3）+ 测试断言 + tarball、重装 web profile 重启实例，请用户复核联系弹窗三卡三码。
