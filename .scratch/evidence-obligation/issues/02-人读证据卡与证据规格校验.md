# 02: 人读证据卡与证据规格校验

**What to build:** 每次 run 自动产出一份人读证据卡（Markdown，落在 run 目录并可从报告与 stderr 尾行找到），一条检查一节：条件（profile/批次/身份行/时间/场景文件）、声称与反例、步骤、观测、证据表（类型/描述/路径/sha256/字节/采集时间）、推断、判定与缺口；卡片只从 run 报告与证据清单渲染，不手写、与 JSON 同源。同时把证据规格中机器可判的部分落成校验：每份证据必须有一行描述（是什么、哪一步取的、看哪里、要证明什么，四要素缺一不可）；截图必须是真的 png 且非空；日志必须带来源路径与行号区间；数据证据必须带关键字段摘要；「正常/成功/没问题」这类不可判定词只做 lint 提示，不改判定。缺项归入义务缺口，出现在报告与卡片里。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 每次 run 在 run 目录落一份 Markdown 证据卡，报告与 stderr 尾行给出路径；卡片可独立打开复核。
- [ ] 卡片一检查一节，包含条件、声称/反例、步骤、观测、证据表、推断、判定与缺口；内容与 run 报告/证据清单一致（有测试锁同源，不允许卡片独有信息）。
- [ ] 证据项支持描述、来源路径、行号区间、关键字段摘要字段；缺描述的证据被点名并计入缺口。
- [ ] 截图证据必须是 png 魔数且非空；日志证据必须带来源路径与行号区间；数据证据必须带摘要；不满足的各自被点名并计入缺口。
- [ ] 不可判定词（正常/成功/没问题等）只记 lint 提示，不影响判定与退出码。
- [ ] 测试覆盖：卡片渲染与 JSON 同源；空描述、假 png、缺行号、缺摘要各自被点名；lint 不误判；typecheck 与 npm test 绿。
