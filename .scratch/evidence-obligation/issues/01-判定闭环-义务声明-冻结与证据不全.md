# 01: 判定闭环：义务声明、冻结与证据不全

**What to build:** 每条真机检查在跑之前就能声明自己要证明什么、需要哪几类证据、拿什么反例能推翻它；run 开始时把这份义务冻结成快照（哈希写进 run 报告），运行中不能改。结算时：pass 但缺必需证据或缺推断 → 该检查记「未决」，整次 run 结论标「证据不全」、退出码 2；fail 不改判但列出缺口；skip/blocked 豁免；旧场景没声明也不报错，而是按「未声明」记未决并提示怎么补。内建步骤（启动、日志、页面等）带默认声称/反例/推断模板，场景作者不必为基础设施写空话。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 场景可以在 step 上声明 claim（可证伪声称）、falsifier（一句反例）、requiredEvidence（证据类型：截图/日志/数据等）、inference（观测后的推断）；加载时校验字段完整与类型合法，坏声明直接报错并指出位置。
- [ ] run 开始即冻结义务快照：run 报告里能看到每条检查的义务与快照哈希；运行中修改声明不影响本次判定；dry-run 计划面同样可见义务。
- [ ] 缺证据或缺推断的 pass 检查记为「未决」并附缺口清单；整次 run 结论为「证据不全」、退出码 2；fail 检查维持 fail 但仍列出缺口；skip/blocked 不判缺口。
- [ ] 未声明义务的存量场景：每条检查记未决并给出「如何声明义务」的提示，不静默通过、也不因缺字段崩溃。
- [ ] 内建步骤有默认声称、反例、推断模板；默认义务下的正常场景能通过，缺证据时按同一规则未决。
- [ ] 测试覆盖全部分支（义务齐全→pass；缺截图→未决/退出码 2；缺推断→未决；未声明旧场景→未决+提示；fail 带缺口仍 fail；skip/blocked 豁免）；typecheck 与 npm test 绿。
