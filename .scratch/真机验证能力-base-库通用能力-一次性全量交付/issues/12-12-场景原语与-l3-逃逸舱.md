## 扩展性对照（票 12 交付证据）

判定口径：旧命令能否只用一个插件仓场景文件（内置步骤 + L3 custom）表达，且不改本能力核心。下表按 `docs/matt-真机验证-第一性原理复盘.md` 的旧真机命令线索取 10 条。

| # | 旧真机命令 | 用哪组原语表达 | 需改核心？ |
|---|---|---|---|
| 1 | launch instance | `launch`（planInstance/executeInstance，隔离 home/profile/workdir） | 否 |
| 2 | stop instance | `stop`（stopRecord，写 stopped.json） | 否 |
| 3 | logs query | `logs`（stdout/stderr tail，可给 bytes/id） | 否 |
| 4 | model status | `model`（readModelConfig + observeCredentialPresence） | 否 |
| 5 | install candidate | `install`（extract/cli，五项安装后核对，可带 candidate） | 否 |
| 6 | skills set | `skills`（六根文件树 + frontmatter + 安装副本） | 否 |
| 7 | check page | `launch` + custom：`context.instance.page()`（url/text/innerSize/pageErrors/screenshot） | 否 |
| 8 | two-instance-smoke | 两次 `launch` + custom：`context.instances` 比较端口/工作区/插件版本 | 否 |
| 9 | isolation probe | `launch` + custom：`context.instance.rawProcess()` / logs / page 检查 | 否 |
| 10 | freeze-candidate | 需 build、npm pack、逐文件 sha256、candidate 判定；当前 `ScenarioContext` 不暴露 ports/command/fs/runtimePaths | **是**（1 条） |

**结论：10 条中 9 条零改核心可表达（9/10 ≥ 8）。** 唯一非零改核心的是 `freeze-candidate`：它需要把构建/打包/哈希/候选判定作为公开原语暴露，或把受控的 ports 子集交给 custom 场景；本次按票面边界没有扩大 `ScenarioContext` 的权限面。

补充：`collect-evidence` 的文本/JSON 部分由 `evidence` 步骤与 run 的 evidence manifest 覆盖；截图二进制登记若也要由场景步骤统一入 manifest，仍需后续扩展（未计入上表 10 条）。
