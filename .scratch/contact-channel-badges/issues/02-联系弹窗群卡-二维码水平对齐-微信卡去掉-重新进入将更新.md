# 02: 联系弹窗群卡：二维码水平对齐 + 微信卡去掉「重新进入将更新」

**What to build:** 联系弹窗三张群卡的二维码要横向对齐（同一水平线），微信卡二维码下方的有效期文案去掉「，重新进入将更新」尾句。

**Blocked by:** None (can start immediately)

**Status:** resolved

## 目的
owner 2026-11-01 视检反馈：① 微信卡二维码下方那句「该二维码 6 天内（11 月 7 日前）有效，重新进入将更新」里的「重新进入将更新」不要写；② 三张卡的二维码目前不在同一水平线上——微信卡副标题删除后二维码上移，需要对齐。

## 维护者原话

出处：本会话（2026-11-01 17:23，owner 附图反馈）
> 如图。微信二维码下面不要写那句“重新进入将更新”。此外这些二维码 水平上应该对齐。

## 背景
- 现状：`packages/base/src/client/modal.ts` 按副标题有无决定二维码前的内容高度；wechat 的 `subtitle` 已在票 `contact-channel-badges/issues/01` 删除，导致其二维码比飞书/QQ 高约一行副标题。
- 有效期文案由 `packages/base/src/core/index.ts` 的 `formatValidity()` 生成（中英双语），当前尾句「重新进入将更新 / refreshed on re-entry」会被拼在这句后面。

## 交付
1. `formatValidity()` 中英双语的尾句「，重新进入将更新 / , refreshed on re-entry」删除，只保留「该二维码 N 天内（M 月 D 日前）有效 / Valid for N days (until M/D)」。
2. 群卡在无副标题时补一个不可见、不可聚焦的副行占位槽，使三张卡的标题区高度一致，二维码顶端横向对齐；有副标题的卡不受影响。
3. 同步更新 `GLOSSARY.md` 里微信卡有效期文案描述，与实现一致。
4. 测试：`validity.test.ts` 文案断言更新；`modal.test.ts` 增加占位槽（微信卡有、飞书/QQ 无）、微信卡 note 不含「重新进入」、以及「每张卡标题与二维码之间恰好一个副行槽」的结构断言。

## 验收判据
- `npm run typecheck && npm test` 全绿；`npm run data:check` 通过（文案是运行时生成，不需要改数据）。
- 真组件截图：三张卡二维码顶边在同一水平线（像素级核对），微信卡 note 为「该二维码 6 天内（11 月 7 日前）有效」，无「重新进入将更新」。
- 无副标题的卡只留空白槽，不引入可聚焦元素或读屏内容。

## 不在范围
